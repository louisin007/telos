### F-01 — JWT Algorithm Confusion (RS256 → HS256)

| | |
|--|--|
| **Severity** | **Critical** |
| **CVSS 3.1** | 9.8 — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H` |
| **OWASP** | A02, A07 / API2:2023 |
| **ATT&CK** | T1539, T1078 |
| **NIST CSF** | PR.AA-01 |
| **CIS** | CIS 16.3 |

**Description:** The JWT validation library accepts HS256-signed tokens without enforcing RS256. The RSA public key is publicly exposed at `/.well-known/jwks.json`. An attacker re-signs any token with HS256 using the public key PEM as the HMAC secret, arbitrarily modifying claims including `role:"admin"`.

**Evidence:**
```
GET /.well-known/jwks.json → HTTP 200 {"keys":[{"kty":"RSA","n":"..."}]}

# Forged HS256 token with role:admin
GET /api/v1/admin/users
Authorization: Bearer <HS256-forged-token>
→ HTTP 200  [full user database returned]
```

**Business Impact:** Complete platform takeover. Admin API access yields all user PII, credentials, and order data. GDPR Article 32 breach notification obligation triggered.

**Reproduction Steps:**
1. `POST /login` → capture RS256 JWT
2. `GET /.well-known/jwks.json` → extract public key PEM
3. Re-sign with `alg:HS256`, set `role:"admin"`, `isAdmin:true`, HMAC key = PEM bytes
4. `GET /api/v1/admin/users` with forged token → HTTP 200

**Remediation:**
- **Immediate/Low:** `jwt.verify(token, publicKey, { algorithms: ['RS256'] })` — never let the client choose the algorithm
- **Short-term/Low:** Rotate the RSA key pair; invalidate all existing sessions
- **Medium-term/Medium:** Monitor logs for anomalous `alg:HS256` tokens

### F-04 — Insecure Deserialization — RCE via Session Cookie
