## 3. Attack Surface Map

Based on public inspection of https://ginandjuice.shop/ (PortSwigger's intentionally vulnerable e-commerce demo):

| Surface Area | Components |
|---|---|
| **Authentication** | Login, registration, password reset, account management |
| **Session Management** | Cookie attributes, JWT tokens, session fixation/hijacking |
| **E-Commerce Logic** | Product catalog, cart, checkout, coupon/discount codes, order history |
| **Search** | Product search (SQLi / XSS surface), filter parameters |
| **File Handling** | Product images, potential upload endpoints |
| **Admin Panel** | `/administrator` or similar privileged interface |
| **APIs** | REST endpoints (`/api/*`), JSON request/response handling |
| **Third-Party Integrations** | Payment gateway redirect flows, OAuth social login |
| **Client-Side** | JavaScript source, DOM-based XSS, prototype pollution, CSP headers |
| **Infrastructure** | HTTP response headers, TLS configuration, server banners |

## 5. Out-of-Scope — Confirm with Client

The following items are **excluded by default** and must be explicitly authorised before testing:

| Item | Reason |
|------|--------|
| Denial of Service (DoS / DDoS) | Risk of service disruption to other users |
| Automated fuzzing at high concurrency | May destabilise shared hosting environment |
| Social engineering of staff | Outside web VAPT boundary |
| Physical access testing | Out of scope for web engagement |
| Third-party payment processor internals (e.g., Stripe, PayPal) | Not owned by client |
| Infrastructure / host OS beyond the web layer | Requires separate network VAPT authorisation |
| Any subdomains not explicitly listed (e.g., `mail.*`, `cdn.*`) | Must be enumerated and approved |
| Data exfiltration of real PII / order data | Sanitised PoC only — never exfiltrate real records |
| Persistent backdoors or payload implants | Single-use PoC only; clean up after each test |
